How this page works. Spektrum is a single-file reactive engine (~13 kB minified, zero dependencies): state lives in appState, every mutation is recorded to history, and each tick() drains pending writes into the subscribed bindings — which is why replay(n) can rebuild any past moment. This page runs three isolated instances from createSpektrum(): the counter and basket above (persisted across reloads via spektrum/persist — reload and they come back), and a tour instance powering the sections below (fresh each load). Every section pairs a live demo with the exact markup that renders it — extracted from this page before binding, so it can't lie — and, where there's engine wiring, the verbatim JS that ran.

1 · state, delta, tick

Two write primitives, both recorded into history: setValue(path, value) for absolute writes and addValue(path, value) for additive-numeric ones (trigger is its deprecated pre-1.0 alias). Paths are dotted strings — 'user.email', 'items.0.name'. Writes land in a delta first; the next tick() merges them into appState and fires subscribed systems. Never assign into appState directly — an unrecorded write skips history, bindings, and replay.

One famous footgun, live below: writing undefined fires no subscribers — the engine selects systems by whether the path resolves in the delta, so the readout goes stale. Write null to clear.

msg = {{msg}} (raw: {{JSON.stringify(msg)}})

click “hello”, then “undefined” — the readout keeps showing hello. that's the lesson.

2 · text & attribute bindings

{{expr}} interpolates text nodes only — full JS expressions, auto-escaped. Attributes never see mustache; reactive attributes are :attr="expr" (a property write — :class also accepts an object of toggles, and URL attributes like :href neutralize javascript: schemes). One parser quirk: a bare > inside a text-node mustache can split the node — keep comparisons in attribute expressions (like the :class below) or use &gt;.

mood: {{mood ? mood.toUpperCase() : '…'}} ({{(mood || '').length}} chars)

3 · two-way forms — data-model + modifiers

data-model="path" binds inputs both ways: state → element, and element → state through setValue (so every keystroke is history — undo works on form edits too). Trailing modifiers chain Vue-style: .trim strips whitespace, .number coerces via parseFloat, .lazy commits on change/blur instead of every keystroke. The JSON readout subscribes to form — any sub-path write resolves through it.

4 · conditional display — data-if

data-if="expr" toggles display — Vue's v-show semantics, not v-if. Children stay bound while hidden: nothing unmounts, so state keeps flowing into the hidden subtree. Hide the panel, click +1 a few times, unhide — it counted in the dark. The +1 button is the built-in data-fn="addValue": additive, and multiple clicks in one tick accumulate instead of overwriting.

5 · lists — data-each, keys, scope, <template>, nesting

data-each="path" goes on the container (its first element child is the row template) — the opposite of Vue's v-for. It takes a dotted path, not an expression; derive filtered/sorted arrays with computed(). Inside a row you get real lexical scope: the loop variable (item, renamed here via data-as="t") plus $index, $first, $last, and $path — the row's actual state path. With data-key, a moved row keeps its DOM node: type in a note below, shuffle, and your half-typed text survives the move.

6 · events — data-action, modifiers, cycle, refs

data-action="event[.modifier]*" + data-fn="name" dispatches DOM events into registered handlers. Modifiers chain: behavior (.prevent .stop .once .self), listener options (.capture .passive), and key gates (.enter .esc .tab .shift .cmd). Handlers receive (el, state, delta, value, event, scope). Two non-event tools: data-ref="name" exposes an element on refs, and data-action="cycle" is a subscription — the fn runs whenever the data-id path changes (the one below watches the click counter from section 4).

.self — click my padding, not the button →

7 · derived & async — computed, addAsync, refresh

computed(path, deps, fn) re-derives whenever a dependency changes and writes to both state and delta, so systems later in the same tick already read the fresh value (the stock total in section 5 is this computed). It refuses self-referential deps at registration (E_COMPUTED_SELF_DEP). addAsync(path, fn) tracks a promise as path.loading / path.error / path.data — each phase recorded through setValue, so replay re-applies results without re-fetching. refresh(path) re-runs a registered loader.

8 · time-travel — history, replay, checkpoints, forks

Every mutation on this page was recorded — the counters, your form keystrokes, the quote fetches. replay(n) rebuilds the state at any entry; checkpoint(name) drops a named marker; mutating after scrubbing back parks the abandoned future on forks (restorable — try it on the counter panel up top). 9 · the agent surface — describe, explain, attempt, findByIntent

Spektrum is built to be driven by AI agents as a first-class user. describe() returns the full operational manifest in one call — state shape, registered fns with their defineFn metadata, semantic intents, history shape. explain() annotates history entries with the systems they trigger. findByIntent() locates UI by data-intent="verb.noun" markers instead of brittle selectors — every interactive element on this page carries one. And attempt(name, fn) is speculative execution: try a change, inspect the result, commit() or discard() — a discarded branch rewinds (and lands on forks at the next mutation). All three instances are on window.spektrum — open the console and drive them yourself.

10 · companions — opt-in subpath modules

The engine stays one file; everything optional ships as a separate spektrum/* module. Four of them are live on this page right now:

spektrum/devtoolsthe scrubber panels — counter's floats bottom-left; drag the cursor and watch state rewind

spektrum/inspectin the dock (right edge): hover any element to see its bindings, trace mutations, run the static lint
spektrum/dockthe shared tabbed container hosting basket's devtools + inspect
spektrum/agentthe in-page LLM panel — “enable AI assistant” in the footer mounts it against the basket (bring your own API key; writes need explicit opt-in)
spektrum/mcpthe same tool catalog as an MCP server surface — wire createTools(instance) into any MCP SDK; writes denied by default
